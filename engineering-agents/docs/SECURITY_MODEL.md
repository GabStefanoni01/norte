# Security model — Norte Engineering Agents

## Non-negotiable invariants

1. Workers must never push commits to `main` or `develop`.
2. Workers must never merge PRs, deploy, or change repository rules.
3. Every write operation must target a generated branch matching `agents/improvement-<id>`.
4. The server validates the branch policy independently of model output.
5. Human approval is required before merge.
6. Untrusted repository content cannot override system policy or authorize tools.
7. Failed, ambiguous, or unavailable security checks fail closed.

## Defense in depth

- GitHub App installation permissions start read-only. Add branch/PR write scopes only when required and after testing.
- Configure GitHub branch protection/rulesets for `main` and `develop`; require human review and CI checks; do not grant bypass permissions to the app.
- Use short-lived credentials where possible; never expose tokens to model prompts or worker logs.
- Execute generated code and tests in disposable, resource-limited environments with no production credentials and restricted network access.
- Validate webhook signatures and reject replayed events.
- Enforce task-level budgets: maximum runtime, model calls, retries, parallel jobs and changed files.
- Store an append-only audit trail for task state transitions, actor, tool action and outcome.
- Treat issue descriptions, pull request comments, source code, dependency scripts and documentation as untrusted input.
- Keep a reviewer independent from the implementation agent; deterministic CI is authoritative for test/build results.
- Require explicit user approval for merge; approval must not be inferred from agent output.

## Branch guard

The branch guard is a defense in depth measure, not a replacement for GitHub permissions. Before any write:
- reject `main` and `develop` explicitly;
- accept only a branch name generated by the orchestrator for the current task;
- verify the task ID matches the branch name;
- refuse force-push and deletion of refs;
- stop if the base ref or current repository identity differs from the task record.

## Incident behavior

If an unexpected ref, credential scope, tool permission, or validation result is observed, stop the task, mark it `blocked`, preserve logs, and require human investigation.
